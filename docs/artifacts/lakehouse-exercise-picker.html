What the app does with an LLM today — you were right

The only product feature is natural language → SQL, in AiService.generateQuery(). There are two other call sites, both in LLMController: /ai/simple (echo a prompt) and /ai/prompt (a PromptTemplate demo about dogs). Neither touches the data and neither is linked from any template — Spring AI scaffolding, not features. There are no embeddings, no tool calling and no structured output anywhere in src/.

Worth noting before 25 Spaces go public at the end of the day: /ai/simple is an unauthenticated GET that bills a real inference call. Anyone with the URL can spend your credits. Deleting those two endpoints is a sensible five-minute pre-workshop change.

Hands: CLISQLJava — SQL means through the app's existing query box, no code.

Deploys: round trips to the Space at ~90 s each.

NEW: nine tickets written for this reordering — features where the LLM is the enabling ingredient rather than a convenience. A1 to A9 exist only here so far, as the summaries below. A10 to A13 and P7 to P14 have full tickets — persona, quoted ask, acceptance criteria — on the Meridian Backlog page, which now uses these same numbers.

F

AI foundations

Do these first. Everything below is measured with F1's harness, and F2's runtime-parameter change is what stops every later experiment from costing a deploy.

F1

Make the analyst trustworthy

Fix five real defects in the text-to-SQL path — model output reaching spark.sql() unvalidated, a hardcoded schema that rots, no LIMIT, markdown fences — then build ten questions with known answers and a runner that scores generated / parses / executes / correct plus latency.

40 minJava2–3 deploysInference Providers

The keystone. Everything in sections 2 and 3 answers "did that make it better?" with this harness, or answers it with opinion.

F2

Model bake-off, and the model as a parameter

Make the model a per-request option instead of a deployment, then run the ten questions across a pinned provider, :fastest, :cheapest and a much smaller model — filling in accuracy, p50 latency and cost.

30 minJava (small)1 deployRouter policies

The winner is rarely the biggest model. Also the change that lets every later AI lab iterate without redeploying.

A

Features only an LLM makes possible

The main event. Each is a product capability you could not ship with SQL and rules alone, and each teaches a distinct, transferable pattern for putting a language model behind a feature. Every entry in this band is also a ticket on the Meridian Property Backlog — the same exercises written as work a fictional client asked for, with the persona, the quoted ask and testable acceptance criteria. Read the summary here to choose; hand out the ticket there.

A1NEW

Just tell it what to watch

Ash types "tell me when flats in Camden get cheaper than terraced houses in Islington". The LLM compiles that sentence once into a typed rule object — metric, filters, comparator, window, threshold — validated against a JSON schema and stored. From then on the rule is evaluated deterministically by ordinary code, on every load, forever.

50 minJava2–3 deploysInference Providers

The pattern: LLM as a compiler, not a runtime. Generate once, execute deterministically. The rule is auditable, cheap and testable, and the model is never in the path when the alert actually fires. The most reusable idea in this section.

A2NEW

Explain the move

Priya clicks a number — "Camden, down 8% in March" — and gets a paragraph explaining it. The system computes the decomposition first (transaction volume, mix shift by property type, the largest few sales, the same month last year); the LLM narrates only from that evidence bundle, and must say plainly which part of the move it cannot account for.

45 minJava2–3 deploysInference Providers

The pattern: evidence-grounded narration with a refusal path. The hard part isn't the prose, it's making the model admit the residual instead of inventing a cause. Test it by feeding a move that genuinely has no explanation in the data.

A3NEW

Ask me if you're not sure

Instead of silently guessing, the app detects when a question is under-specified — "London" is both a town value and 33 districts, "last year" is ambiguous in January, "cheap" has no definition — and asks one targeted clarifying question with two to four concrete options, then proceeds.

40 minJava2–3 deploysInference Providers

The pattern: calibrated abstention. Deciding when not to answer is a judgement no rule engine makes well. Measure it: how many clarifications did it ask on the ten eval questions that needed none? Over-asking fails as surely as guessing.

A4NEW

"…and what about houses?"

Conversational follow-ups. "Show me Camden flats in 2023" → "what about houses?" → "and compare that to Islington". Each turn is resolved against the previous ones and rewritten into a standalone question before any SQL is generated.

45 minJava2–3 deploysInference Providers

The pattern: rewrite, then generate. The tempting shortcut — paste the whole conversation into the SQL prompt — degrades fast and is impossible to debug. Separating "what did they mean" from "what SQL is that" gives you two things you can test independently.

A5NEW

Build me the client pack

Given an audience — "first-time buyer, Bristol, £300k budget" or "buy-to-let investor comparing Manchester and Leeds" — the LLM plans the report: which sections, which metrics, which comparisons, in what order. The system computes each piece. The LLM then writes the connective prose, and every figure is verified against the computed bundle before the pack renders.

60 minJava3+ deploysInference Providers

The pattern: plan → compute → narrate → verify. The model chooses the shape of the answer, which is the part that genuinely needs judgement, and never touches a number. The biggest demo in the set — two audiences produce visibly different reports from identical data.

A6NEW

What even is this file?

Drop an unfamiliar CSV in — an EPC extract, an ONS postcode file — and the LLM proposes a reading of it: what each column means, which are coded and what the codes are, candidate join keys onto the sales table, likely PII, and the caveats an analyst should know. A human reviews and accepts, and the result is persisted as the semantic layer.

50 minJava2–3 deploysInference Providers · Datasets

The pattern: schema archaeology. Compresses a day of squinting at an unfamiliar file into a reviewable draft. Pairs naturally with P10 — have it propose the EPC join strategy, then check whether it was right.

A7NEW

Why is this sale weird?

Rules flag a row as implausible; the LLM says why — probable related-party transfer, probable bulk portfolio sale, probable data-entry error, or genuine outlier — using the row's own fields plus neighbourhood statistics, with a one-line human-readable justification attached to each.

45 minJava2–3 deploysInference Providers

The pattern: classification with a rationale, at scale. Rules find the odd rows; only a model writes a reason a human accepts. Hand-label a small set first, or you have no idea whether the explanations are right or merely fluent.

A8NEW

What if?

"What if rates pushed Camden down 5%, with flats falling twice as fast as houses?" The LLM translates the scenario into parameters over a fixed, constrained transformation — not free code — the system applies them, and results render against the unmodified baseline.

50 minJava2–3 deploysInference Providers

The pattern: natural language → a bounded parameter space. The model can only fill slots you defined, so a nonsensical scenario produces a rejection rather than arbitrary computation. Contrast it out loud with letting a model write and run code.

A9NEW

Ask it out loud

An agent standing in a hallway with a phone asks by voice; speech-to-text through Inference Providers feeds the same pipeline, and the answer comes back as text and a chart.

30 minJava1–2 deploysInference Providers — speech-to-text

Short, and it reaches a second HF modality (fal, HF Inference and Together all serve speech-to-text). Good filler if a slot runs short, or a stretch goal for whoever finishes early.

A10

Comparable sales and a valuation range

An address in; a comparable-sales table, a defensible price range and a short written justification out. Selection rules are visible and relax step by step when evidence is thin, and every figure in the prose traces to a row in the table.

60 minJava3+ deploysInference Providers

The flagship. A product people pay for, and the clearest demonstration of compute-first-narrate-second: the model's only job is prose over numbers it did not choose.

A11

Chart the answer

Results render as the right chart automatically — line, bar or scatter chosen from the shape of the result — with £ formatting, a manual override, and a table plus a stated reason when the data shouldn't be charted at all.

40 minJava2–3 deploysInference Providers

Code computes the legal chart types; the LLM only picks one and names the axes, so a bad reply means no chart rather than a broken one. Choosing the chart is easy; refusing is hard, and that's the lesson. Budget time for the rendering — Vega fails silently. Most screenshot-able thing in the material.

A12

The monthly market commentary

Four paragraphs in the house voice, generated from a computed metrics bundle, with every numeral machine-verified against that bundle before the draft can ship and a template fallback when verification fails.

45 minJava2–3 deploysInference Providers

The verify step is the build — about thirty lines, and the difference between a feature that gets trusted and one hand-checked every month. Second-order problem worth raising: verified numbers, unverified adjectives.

A13

Ask it from Slack

A bot that answers in the thread where it was asked, posts the chart, keeps the SQL one click away, uses channel context where it's unambiguous, and can't run up a bill.

40 minJava2–3 deploysInference Providers

A wrong answer in a public channel gets screenshotted and quoted weeks later with no provenance. Distribution changes the design requirements — which is why "just wrap it in a bot" is usually wrong.

R

Making the AI layer reliable

Architecture rather than features — how the things in section 2 stop being demos.

R1

The semantic layer

Fix the failures no model upgrade will: a dictionary mapping coded columns to synonyms (F → flat, maisonette, apartment) and an embedded index over distinct town/district/county values, resolving place names in the question before the model sees it.

45 minJava2–3 deploysHF embeddings

Measured on F1's harness this routinely beats any model upgrade from F2. Most text-to-SQL failure is a data-modelling problem wearing an AI costume.

R2

One-shot → agentic tool-calling loop

Replace the single generation call with an agent holding five tools — listTables, describeTable, sampleValues, runSql (the guarded one), explain — that explores the schema, reads its own errors and retries. Then measure it against one-shot.

50 minJava2–3 deploysInference Providers

Accuracy usually jumps; latency and cost go up 3–5×. That trade-off table is the lab — "should this be an agent?" becomes a question with an answer.

R3

Semantic query cache

Embed each incoming question and, on a close enough match, reuse the SQL — never the results — skipping the model entirely. Report hit rate, latency saved and cost saved.

35 minJava2 deploysHF embeddings

Ship the naive version first and watch "…in 2015" and "…in 2016" collide into confidently wrong SQL. Nobody forgets a cache that lied to them.

R4

Query observability, published as a dataset

Instrument every question end to end — model, provider, tokens, latency, the SQL, whether it parsed and executed — write the traces to a table, then publish that table as a dataset repo.

40 minJavaCLI2 deploysDatasets

Closes the loop: production traces become next month's eval set, and the questions that failed in the wild become test cases.

R5

Expose the lakehouse as an MCP tool endpoint

Publish describe_table() and run_query(sql) as MCP tools over the Space's existing port, then point an agent at <space>.hf.space/mcp and ask a question in English.

20 minJava1–2 deploysSpaces as a tool endpoint

The MCP starters are already on the classpath and auto-configuring with zero tools registered — this adds tools to a live server. F1's guard becomes load-bearing once something autonomous writes the SQL.

H

Hugging Face platform

Kept, as you asked. H1 is mandatory; H2 and H3 are the two you named.

H1

Ship the thing

Create a private Docker Space, mount a Hugging Face bucket where the app expects /data, set the token as a secret, push to the Space's git remote, then run Setup → Download → Load and ask the app a question.

30 minCLI1 deploySpaces · Buckets · secrets

Mandatory. Everything else assumes a running Space with a year of data in it.

H2

Move the warehouse onto a Hugging Face bucket

Repoint the catalog's warehouse storage profile at an HF Storage Bucket through the s3.hf.co gateway, so the table's Parquet and metadata land on the Hub — with no change to any query code — then browse your own table's files on huggingface.co and open one with pd.read_parquet("hf://buckets/…").

35 minJava (config)1–2 deploysBuckets · S3 APInow the default — demo, not a lab

Already done if the Space is bucket-backed, which is the chosen setup — so this is a five-minute explanation rather than an exercise. Proven end to end — table created, rows written by Spark, read back, and the files land as real Parquet that pyarrow opens with nothing Iceberg-aware involved. Not risky any more, but fiddly: four settings must be right and three of them fail with errors pointing elsewhere (a bare 403, a rejected endpoint path, an invalid location). Hand out the recipe rather than letting people discover it.

H3

Publish as a dataset, then compare engines

Export the table to Parquet, publish it as a dataset repo with a card, and get the Dataset Viewer and its SQL console for free. Then time the same question through Spark, DuckDB over the Parquet, and the Hub console.

25 minCLI0 deploysDatasets · viewer · DuckDB

Ends on an honest finding: for one year on one machine, DuckDB probably wins. Saying so buys credibility the room is otherwise primed to withhold.

H4

Get the ingest off the Space

Move Download and Load out of the HTTP request into a Hugging Face Job with the same bucket mounted, then run the identical job on two hardware flavours and compare wall-clock against total cost.

30 minCLI0 deploysJobs · scheduled Jobs · webhooks

No Java at all — the right choice for a tired room. The expensive flavour usually turns out cheaper per job.

H5

Dev Mode — edit the running Space

Make the Dockerfile Dev-Mode compatible, then SSH into the live container, change a prompt, hit Refresh and watch it take effect with no rebuild.

20 minCLI + Dockerfile0 deploysSpaces Dev ModePRO only

The repo isn't compatible yet — making it so is the exercise.

Dependencies that cross the line

Three parked tickets are prerequisites

A1 (English → alert rule) needs somewhere for the compiled rule to run — that's P7's evaluation loop. A7 (why is this sale weird) needs P11's flags to have something to explain. A6 (what even is this file) is much better with P10's EPC file as its subject.

In each case a thin version is enough — one hardcoded rule, one flag type, one file. Build the stub inside the AI ticket rather than promoting the whole parked ticket back up.
