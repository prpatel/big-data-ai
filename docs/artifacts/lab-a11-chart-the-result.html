Lab A11 · Meridian ticket · 40 minutes · you write the code

Don't make me read a table

Make results render as the right chart automatically — and, harder, make the tool refuse to chart the things it shouldn't.

The ticket · Priya, who builds client decks

"When I ask how prices have moved in Camden I get two hundred rows of numbers. I need the picture. I'm pasting these into client decks and I'm currently rebuilding every one of them in Excel."

This is a build lab. You write code, push, and check it on your Space. It assumes F1 — you will reuse the structured-output pattern from SqlAnswer.

Read this before you start, it is the whole lab

Choosing a chart is easy. Refusing is hard, and it is where every naive version of this falls over. The decision is a function of the result shape — how many columns, of what types, how many rows — not of the question.

So the order matters: compute the shape first, then let the model choose only within what is already legal. Constrain, then ask. If you ask the model to decide freely you will get a pie chart of two hundred towns.

Part 2

Compute the shape

10 min
2.1

Create the record

new file · src/main/java/dev/prpatel/iceberg/app/ResultShape.java 
public record ResultShape(
        long rowCount,
        List<String> columns,
        List<String> types,        // spark type names: date, string, int, double…
        int categoryColumns,       // string columns
        int measureColumns,        // numeric columns
        boolean hasTemporal) {     // any date/timestamp column

    /** What this shape is allowed to become. Computed, never asked. */
    public List<String> allowedCharts() {
        if (rowCount <= 1 || rowCount > 5000) return List.of();
        if (columns.size() > 3)               return List.of();
        // TODO: line when hasTemporal && measureColumns >= 1
        // TODO: bar  when categoryColumns == 1 && measureColumns == 1
        // TODO: scatter when measureColumns >= 2
        return List.of();
    }
}

Do not call count() on an uncapped result

F1 part 2 was about exactly this. The guard already applied a LIMIT, so count the rows you actually took — takeAsList gives you them — rather than scanning the table again to find out how many there were.

The prompt must not offer a free choice
  • Give it the column names and types, and the row count
  • Give it only the chart types allowedCharts() returned — not the full menu
  • Ask for JSON in the ChartChoice shape, nothing else
  • Never call this when allowedCharts() is empty. If nothing is legal there is nothing to ask, and asking anyway is how you get the pie chart
3.3

Validate what comes back

The model can still name a column that is not in the result, or a chart type you did not offer. Check both against the shape before rendering — this is the same idea as columns_used in F1: ask for fields you can verify.

4.2

Two outcomes in the fragment

src/main/resources/templates/runqueryresult.html

It currently renders one thing. Give it two, and always keep the table:

Do this
  • a <div id="chart"> plus a small script calling vegaEmbed, when a chart was chosen
  • the existing table underneath it, always — the chart is an addition, not a replacement
  • when no chart: the table plus a one-line reason. Not silence. "Not charted: a single value", "Not charted: 4,812 rows"
Change the target first

In index.html the element htmx swaps into is <pre id="queryresult"> — left over from when the result was only ever text. A chart inside a <pre> gets no layout width and draws nothing. Make it a <div>, and give the table its own <pre> inside the fragment instead.

4.3

Money and dates, or Priya will not use it

An unformatted axis of 3.9e5 is not going in a client deck. But the obvious way to write this is a trap:

This one costs people twenty minutes

"axis": {"format": "£,.0f"} looks right and is not. d3-format only accepts its own $ currency placeholder; a literal £ voids the whole format string. Vega then lays the chart out with zero-sized marks and no axis padding — you get a blank plot, no exception, nothing in the console, and a promise that resolves happily.

Put "$,.0f" in the spec, and supply the actual symbol as a locale when you embed:

var GBP = {decimal: '.', thousands: ',', grouping: [3], currency: ['\u00A3', '']};
vegaEmbed('#chart', spec, {formatLocale: GBP});

Dates: let the temporal type do the work, but pin the label angle yourself — "axis": {"labelAngle": -45} for dates, 0 for categories. Vega decides rotation on a first layout pass and never revisits it, which matters for the reason in 4.4.

4.4

When the chart comes out blank

It will, at least once. Every failure in this feature is silent — no exception, no console error, no rejected promise — so work down this list rather than staring at the spec:

Triage, in order
  1. Is the container zero-wide? Run document.getElementById('chart').offsetWidth in the console after the chart renders. vega-embed puts its own class on the element you hand it, and that class is display:inline-block — which shrink-wraps the very container width:"container" is trying to measure. Force it back: #chart, #chart.vega-embed { display:block; width:100%; }
  2. Is it still inside a <pre>? See 4.2.
  3. Is a format string voiding the layout? Drop every format from the spec. If the chart appears, that was it — see 4.3.
  4. Did the marks actually get built? Render with {renderer:'svg'} and look at the mark paths. M0,0h0v0h0Z means zero-sized marks: the data reached Vega but the layout failed, which points at 1 or 3, not at your data.

Worth noticing: the scenegraph will happily report five rect marks while the canvas shows nothing. "Vega thinks it drew it" and "you can see it" are different claims, and only the second one is the acceptance criterion.
